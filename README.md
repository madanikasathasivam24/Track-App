# Track — Frontend

Real-time group location and travel coordination app (React Native + Expo, managed workflow).

## Running the app

1. Copy `.env.example` to `.env` and point `EXPO_PUBLIC_API_URL` at your backend (defaults to `http://https://track-api-fjkl.onrender.com`).
2. `npm install`
3. `npx expo start` — scan the QR code with Expo Go, or press `a` / `i` for an emulator/simulator.

Auth (Signup, Login) and the Groups list are fully implemented. Everything under `LiveMapScreen`'s
real map/socket logic, Alerts, LiveShare, and Friends is a scaffolded placeholder pending review of
this first pass.

## Native config for react-native-maps

- **Both iOS and Android use Google Maps** (`PROVIDER_GOOGLE`), not Apple Maps on iOS — needed for
  consistent custom styling and traffic behavior on both platforms. Set
  `GOOGLE_MAPS_API_KEY_ANDROID` / `GOOGLE_MAPS_API_KEY_IOS` in `.env` (see `.env.example`) — these
  are read by `app.config.js` at `expo prebuild`/`expo run:*` time and baked into
  `AndroidManifest.xml`/`Info.plist`, not shipped into the JS bundle. Get keys from the
  [Google Cloud Console](https://console.cloud.google.com/), restricted to Maps SDK for
  Android/iOS respectively and to this app's package name/SHA-1 or bundle ID — see `CLAUDE.md` for
  the full key-restriction table.
- Since this project uses native modules (maps, secure store, gesture handler, reanimated), you're
  in the Expo **managed workflow with a dev client** — plain Expo Go won't include the native map
  module. Run `npx expo run:android` / `npx expo run:ios` (or build a dev client with EAS) rather
  than relying on the classic Expo Go app once you get to LiveMapScreen.

## Avatars

The 5 files in `src/assets/avatars/` are solid-color placeholders generated by
`scripts/gen-placeholder-avatars.js` so the app runs without missing-asset errors. Replace them with
real artwork before shipping (see chat notes on sourcing from Freepik).
